# Implementation Plan: AI-Powered Restaurant Recommendation System

This document outlines a phase-wise implementation plan for building the AI-powered restaurant recommendation system, leveraging FastAPI, Pandas/DuckDB, Streamlit, and the Groq API (Llama 3).

## Phase 1: Project Setup & Environment Configuration
**Goal:** Initialize the repository, define dependencies, and establish the project structure.

1.  **Initialize Repository:** Set up Git and create the basic folder structure (`/backend`, `/frontend`, `/data`, `/notebooks`).
2.  **Environment Setup:** Create a `requirements.txt` or `pyproject.toml` including:
    *   `fastapi`, `uvicorn`
    *   `pandas`, `datasets` (Hugging Face)
    *   `groq`, `python-dotenv`
    *   `streamlit`
3.  **API Keys:** Set up `.env` for the Groq API Key and Hugging Face token (if required).

## Phase 2: Data Ingestion & Preprocessing
**Goal:** Fetch, clean, and store the Zomato dataset so it is ready for querying.

1.  **Data Fetching Script:** Write a Python script using the Hugging Face `datasets` library to pull `ManikaSaini/zomato-restaurant-recommendation`.
2.  **Data Cleaning:**
    *   Handle null/missing values in critical columns (e.g., location, cost, rating).
    *   Standardize text (lowercase, strip whitespace) for locations and cuisines.
    *   Map numerical costs to budget tiers (Low, Medium, High).
3.  **Data Storage:** Save the cleaned dataset as a local CSV or Parquet file, or initialize a local SQLite/DuckDB database for rapid querying by the backend.

## Phase 3: Backend API & Data Filtering Engine
**Goal:** Build the FastAPI server and the logic to filter candidates based on hard constraints.

1.  **FastAPI Setup:** Initialize the FastAPI app and define the `/recommend` POST endpoint.
2.  **Request Models:** Create Pydantic models for the user request payload (location, budget, cuisine, min_rating, preferences).
3.  **Pre-filtering Logic:** 
    *   Load the cleaned data into memory (Pandas DataFrame) or connect to the database on startup.
    *   Implement the filtering function: take user's hard constraints (Location, Budget, Cuisine, Rating) and return the Top 15 matching restaurants.
4.  **Testing:** Test the endpoint locally with tools like Postman or cURL to ensure it successfully filters and returns candidate restaurants.

## Phase 4: LLM Integration (Groq API)
**Goal:** Connect the backend to Groq to generate reasoning and final rankings.

1.  **Groq Client Setup:** Initialize the Groq client in the backend.
2.  **Prompt Engineering:**
    *   Draft the System Prompt defining the AI concierge persona.
    *   Draft the User Prompt template that dynamically injects user preferences and the pre-filtered JSON data of restaurants.
3.  **Integration:**
    *   Update the `/recommend` endpoint to pass the filtered candidates to the Groq API.
    *   Define a JSON schema/function calling structure to ensure Groq returns a structured array of recommendations (Name, Cuisine, Rating, Cost, AI Explanation).
4.  **Error Handling:** Implement fallbacks in case the LLM fails or the user provides constraints that yield no candidates in Phase 3.

## Phase 5: Frontend Development
**Goal:** Create a user-friendly interface to capture preferences and display results.

1.  **Streamlit App Initialization:** Create `app.py` in the `/frontend` directory.
2.  **Input Form:** Build UI components (dropdowns, sliders, text inputs) for capturing Location, Budget, Cuisine, Minimum Rating, and extra preferences.
3.  **API Integration:** Write the logic to send the form payload to the FastAPI `/recommend` endpoint via `requests`.
4.  **Result Rendering:** Parse the JSON response and render the ranked restaurants clearly, highlighting the AI-generated explanations.

## Phase 6: Testing & Optimization
**Goal:** Ensure the system is robust, performant, and accurate.

1.  **Latency Optimization:** Ensure the data pre-filtering is fast and that the Groq LLM calls return quickly (Llama 3 on Groq is typically very fast).
2.  **Prompt Tuning:** Review the explanations generated by the LLM and tweak the prompt to make them more natural, concise, or engaging.
3.  **Edge Cases:** Test with extreme constraints (e.g., highly restrictive filters) to ensure the UI gracefully handles "No restaurants found" scenarios.

## Phase 7: Deployment
**Goal:** Make the application accessible on the web using Streamlit Community Cloud.

1.  **Backend Merge:** The FastAPI backend has been merged directly into `app.py`. All filtering + Groq LLM logic now runs in-process — no separate server needed.
2.  **Data Strategy:** The dataset loads from Hugging Face at runtime via `@st.cache_data`, eliminating the need to ship the 585MB database.
3.  **Streamlit Cloud Deployment:** Push to GitHub, connect the repo on [share.streamlit.io](https://share.streamlit.io), set main file to `frontend/app.py`, and configure Groq API secrets in the dashboard.
